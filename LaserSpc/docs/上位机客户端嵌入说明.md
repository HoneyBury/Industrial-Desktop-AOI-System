# LaserSpc 嵌入上位机客户端说明

本文说明如何将当前项目作为 `CMake + Qt` 子模块嵌入到你的上位机客户端中。

## 1. 当前可嵌入形态

项目已经拆成以下目标：

- `LaserSpcCore`
  - 业务服务、仓储、配置、导出、写入逻辑
- `LaserSpcUi`
  - 看板页面、主题、对话框、`DashboardWidget`
- `LaserSpc`
  - 独立运行的壳程序
- `LaserSpcIngestServer`
  - HTTP 写入适配器

如果你的客户端本身也是 Qt 桌面程序，推荐直接嵌入 `DashboardWidget`，不要再通过启动 `LaserSpc.exe` 的方式做进程间集成。

## 2. 推荐集成方式

推荐方式：

1. 把 `LaserSpc` 仓库作为子目录或子模块放到你的客户端工程中
2. 在客户端 `CMakeLists.txt` 中 `add_subdirectory(...)`
3. 客户端目标直接链接 `LaserSpcUi`
4. 在你的页面或子窗口里创建 `LaserSpc::Ui::DashboardWidget`

这样做的优点：

- UI、业务逻辑、配置读取都保持一份代码
- 你的客户端和 SPC 看板可以统一发布
- 不需要维护单独进程生命周期
- 后续如果你只想嵌业务层，也可以只链接 `LaserSpcCore`

## 3. 目录接入示例

假设你的客户端工程目录如下：

```text
HostClient/
  CMakeLists.txt
  src/
  third_party/
    LaserSpc/
```

## 4. CMake 集成示例

客户端顶层 `CMakeLists.txt` 可参考：

```cmake
cmake_minimum_required(VERSION 3.16)

project(HostClient LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

find_package(QT NAMES Qt6 Qt5 REQUIRED COMPONENTS Core Gui Widgets Sql Charts Concurrent Network)
find_package(Qt${QT_VERSION_MAJOR} REQUIRED COMPONENTS Core Gui Widgets Sql Charts Concurrent Network)

add_subdirectory(third_party/LaserSpc)

add_executable(HostClient
    src/main.cpp
    src/MainWindow.cpp
    src/SpcContainerPage.cpp
)

target_link_libraries(HostClient PRIVATE
    Qt${QT_VERSION_MAJOR}::Core
    Qt${QT_VERSION_MAJOR}::Gui
    Qt${QT_VERSION_MAJOR}::Widgets
    LaserSpcUi
)
```

说明：

- `LaserSpcUi` 会自动依赖 `LaserSpcCore`
- 你的客户端无需重复手工列出 LaserSpc 源码文件
- 如果你的工程已经统一 `find_package(Qt...)`，保持 Qt 版本一致即可

### 4.1 仓库内可直接编译的宿主示例

当前仓库已经增加了一个宿主示例目标：

- `LaserSpcHostWriterSupport`
- `LaserSpcHostWriterExample`

可以直接这样编译：

```bash
cmake -S . -B build -DLASERSPC_BUILD_HOST_WRITER_EXAMPLE=ON
cmake --build build --target LaserSpcHostWriterExample
```

对应目录：

- `examples/host_spc_writer/`

这个示例会：

- 左侧嵌入 `DashboardWidget`
- 右侧提供宿主写入控制面板
- 演示同步写、异步单写线程、按 `boardCode` 聚合后 flush

## 5. 代码嵌入示例

### 5.1 在宿主页面中嵌入 `DashboardWidget`

```cpp
#include <QVBoxLayout>
#include <QWidget>

#include "app/AppServiceFacade.h"
#include "infrastructure/AppConfigService.h"
#include "infrastructure/RepositoryFactory.h"
#include "ui/shell/DashboardWidget.h"

class SpcContainerPage : public QWidget {
public:
    explicit SpcContainerPage(QWidget* parent = nullptr) : QWidget(parent) {
        auto* layout = new QVBoxLayout(this);
        layout->setContentsMargins(0, 0, 0, 0);

        LaserSpc::Infrastructure::AppConfigService configService;
        auto buildResult = LaserSpc::Infrastructure::RepositoryFactory::build(configService.settings());

        m_facade = std::make_unique<LaserSpc::App::AppServiceFacade>(
            std::move(buildResult.repository),
            buildResult.dataSourceMode);

        m_dashboard = new LaserSpc::Ui::DashboardWidget(m_facade.get(), this);
        layout->addWidget(m_dashboard);
    }

private:
    std::unique_ptr<LaserSpc::App::AppServiceFacade> m_facade;
    LaserSpc::Ui::DashboardWidget* m_dashboard = nullptr;
};
```

### 5.2 关键点

- `AppServiceFacade` 生命周期必须长于 `DashboardWidget`
- `DashboardWidget` 本身就是 `QWidget`，可以直接放进：
  - `QTabWidget`
  - `QStackedWidget`
  - `QMdiSubWindow`
  - 普通 `QVBoxLayout/QHBoxLayout`

## 6. 主题与宿主样式

当前版本已将主题应用收敛到 `DashboardWidget` 自身，不再通过全局 `QApplication::setStyleSheet(...)` 覆盖宿主程序。

这意味着：

- 宿主程序自己的主题仍然可以保留
- LaserSpc 看板会以自身样式显示
- 如果你希望进一步统一视觉，可以在宿主中扩展 `UiTheme`

## 7. 数据源初始化方式

默认情况下，推荐复用当前的仓储工厂：

```cpp
LaserSpc::Infrastructure::AppConfigService configService;
auto buildResult = LaserSpc::Infrastructure::RepositoryFactory::build(configService.settings());
```

如果你希望由宿主客户端统一管理数据库配置，也可以直接自己构建仓储后传入：

```cpp
auto repository = std::make_unique<LaserSpc::Infrastructure::MySqlSpcRepository>(databaseSettings);
auto facade = std::make_unique<LaserSpc::App::AppServiceFacade>(std::move(repository), "MySQL Repository");
```

## 8. 写入模式建议

如果宿主客户端只负责看板展示：

- 查询：直接嵌入 `DashboardWidget`
- 写入：继续保留 `LaserSpcIngestServer` 或宿主内部直接调用 `IngestService`

如果宿主客户端既展示又写入：

- 查询走 `AppServiceFacade`
- 写入走 `IngestService`
- 不建议让宿主自行绕过业务层直接写 SQL

## 9. 发布建议

推荐发布方式：

1. 宿主客户端直接静态/动态链接 `LaserSpcUi` 与 `LaserSpcCore`
2. 如有外部设备 HTTP 写入需求，再单独发布 `LaserSpcIngestServer`
3. 配置文件由宿主统一管理，或约定独立 `ini` 路径

## 10. 当前版本适合的集成方案

对你当前场景，最合适的是：

- 看板作为宿主客户端的一个子窗口或分页
- 业务代码直接链接 `LaserSpcUi`
- 不做插件化
- 不再复制源码到宿主主工程里做二次分叉

这样后续维护成本最低。
