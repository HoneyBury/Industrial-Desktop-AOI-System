# LaserSpc 项目配置说明书

## 1. 适用范围

本文档用于说明 `LaserSpc` 项目的运行配置、环境变量、数据库初始化、配置文件位置以及生产环境建议。

## 2. 配置优先级

项目配置按以下优先级生效：

1. 环境变量
2. `config/laserspc.ini`
3. 程序内默认值

说明：

- 如果环境变量和 `ini` 同时配置，环境变量优先。
- 配置中心保存的是 `ini` 文件。
- 数据库初始化工具 `LaserSpcDbInit.exe` 读取环境变量，不读取配置中心界面状态。

## 3. 配置文件

默认配置文件路径：

`<程序目录>/config/laserspc.ini`

可通过环境变量覆盖：

`LASERSPC_CONFIG_FILE`

示例：

```ini
[general]
use_mysql=1
system_settings_enabled=1
export_report_enabled=1
default_query_days=7
auto_refresh_enabled=0
auto_refresh_interval_seconds=60

[cleanup]
production_retention_days=30

[ui]
language=zh_CN
theme_style=ocean

[mysql]
host=127.0.0.1
port=9527
database_name=laser_spc
user_name=root
password=zjh123456
connect_options=
connect_timeout_seconds=5
read_timeout_seconds=15

[mes]
enabled=0
endpoint_url=
site_code=
station_code=
user_name=
timeout_seconds=8

[report]
title=LaserSpc SPC 报告
customer_name=
footer_text=LaserSpc 自动生成
logo_path=
```

## 4. 环境变量说明

### 4.1 通用

- `LASERSPC_CONFIG_FILE`
  - 指定配置文件路径
- `LASERSPC_USE_MYSQL`
  - 是否优先使用 MySQL，支持 `1/0/true/false/off`
- `LASERSPC_SYSTEM_SETTINGS_ENABLED`
  - 系统设置入口是否可用
- `LASERSPC_EXPORT_REPORT_ENABLED`
  - 导出报表功能是否可用

### 4.2 MySQL

- `LASERSPC_DB_HOST`
  - MySQL 主机地址
- `LASERSPC_DB_PORT`
  - MySQL 端口
- `LASERSPC_DB_NAME`
  - 业务库名
- `LASERSPC_DB_USER`
  - 登录用户名
- `LASERSPC_DB_PASSWORD`
  - 登录密码
- `LASERSPC_DB_CONNECT_OPTIONS`
  - Qt MySQL 驱动连接参数
- `LASERSPC_DB_CONNECT_TIMEOUT_SECONDS`
  - 连接超时秒数
- `LASERSPC_DB_READ_TIMEOUT_SECONDS`
  - 读取超时秒数

### 4.3 报告模板

- `LASERSPC_REPORT_TITLE`
- `LASERSPC_REPORT_CUSTOMER`
- `LASERSPC_REPORT_FOOTER`
- `LASERSPC_REPORT_LOGO`

### 4.4 数据清理

- `LASERSPC_PRODUCTION_RETENTION_DAYS`
  - 生产数据保留天数

### 4.5 数据库初始化工具

- `LASERSPC_ADMIN_DB`
  - 初始化时连接的管理库，默认 `mysql`
- `LASERSPC_DB_SEED`
  - 是否允许自动灌入演示种子数据，默认开启

## 5. 配置中心说明

系统设置入口包含以下几个模块：

### 5.1 数据源

- 是否优先使用 MySQL
- 主机、端口、数据库名、用户名、密码
- 连接超时、读取超时
- 默认查询天数
- 自动刷新开关与刷新周期

补充：

- `system_settings_enabled` 和 `export_report_enabled` 主要供环境变量或外部 API 控制
- 客户端读取到这两个开关后，会分别禁用系统设置入口和导出报表功能

### 5.2 数据清理

- 生产保留天数
- `清理种子数据`
  - 删除项目内置演示数据
- `清理生产数据`
  - 删除指定保留天数之前的数据

说明：

- 数据清理仅支持 MySQL 数据源。
- 清理动作直接操作数据库，不经过回收站。
- 建议生产环境先做数据库备份，再执行清理。

### 5.3 报告模板

- 报告标题
- 客户名称
- 页脚说明
- Logo 路径

## 6. 数据库初始化与升级

### 6.1 工具职责

`LaserSpcDbInit.exe` 仅负责：

- 建库
- 建账号与授权
- 迁移脚本版本管理
- 表结构升级
- 空库场景下的种子初始化

它不再负责业务数据清理。

### 6.2 初始化步骤

1. 配置好 MySQL 连接环境变量
2. 运行 `LaserSpcDbInit.exe`
3. 工具按 `LASERSPC_DB_NAME / LASERSPC_DB_USER / LASERSPC_DB_PASSWORD` 动态建库和授权
4. 再执行 `sql/mysql/migrations` 下的迁移脚本
5. 如果业务表为空，则按配置决定是否灌入种子数据

当前 Windows + Qt 5.15.2 环境下，默认 MySQL 连接参数已经带上兼容配置：

- `MYSQL_OPT_SSL_ENFORCE=0`
- `MYSQL_OPT_SSL_VERIFY_SERVER_CERT=0`

这套默认值用于兼容本地 MySQL 5.5 和较新的 MySQL 8/9 环境，避免初始化阶段因为 SSL 协商失败直接中断。

补充：

- 当前初始化主入口只有 `LaserSpcDbInit.exe`。
- 表结构升级统一由 `sql/mysql/migrations` 维护。
- 种子数据脚本保留为 `seed_data.sql` 和 `seed_point_records.sql`，供初始化工具和回归恢复流程调用。

### 6.3 数据库重建步骤

当本地开发库需要完整重建时，建议按下面流程执行：

1. 确认当前使用的是本地 MySQL，而不是 Docker 或其他共享实例。
2. 先备份需要保留的数据。
3. 删除旧业务库，或改用新的业务库名和业务账号。
4. 设置初始化环境变量：

```powershell
$env:LASERSPC_DB_HOST = "127.0.0.1"
$env:LASERSPC_DB_PORT = "3306"
$env:LASERSPC_ADMIN_DB = "mysql"
$env:LASERSPC_ADMIN_DB_USER = "root"
$env:LASERSPC_ADMIN_DB_PASSWORD = "zjh123456"
$env:LASERSPC_DB_NAME = "laser_spc"
$env:LASERSPC_DB_USER = "laserspc"
$env:LASERSPC_DB_PASSWORD = "LaserSpc#2026"
$env:LASERSPC_DB_SEED = "1"
```

5. 执行数据库初始化工具：

```powershell
D:\Program\spc\LaserSpc\build-msvc-qt5\Debug\LaserSpcDbInit.exe
```

6. 初始化成功后，至少确认以下内容：

- 业务库已创建
- 业务用户已创建
- `localhost` 与 `%` 授权已生效
- `board_records`、`point_records`、`schema_migrations`、`schema_version` 已存在
- 如果开启种子导入，`board_records` 中已有样例数据

注意：

- MySQL 5.5 用户名长度上限为 16，重建时业务用户名不要超过 16 个字符。
- `LaserSpcDbInit.exe` 现在会同时处理建库、建用户、授权、迁移和种子导入，不建议再手工拆开执行旧版 SQL。

### 6.4 本地回归脚本

如果需要对“数据库重建模块”做一键回归验证，直接运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools\Run-DbInitRegression.ps1
```

当前脚本默认只验证本地 `3306` MySQL，不再跑 Docker，也不再触发 `LaserSpcTests`。脚本会自动完成：

- 用两组隔离测试库和测试账号执行 `LaserSpcDbInit.exe`
- 校验账号是否创建成功
- 校验授权是否存在
- 校验核心表是否完整生成
- 用业务账号登录并检查表和样例数据
- 输出报告到 `build-msvc-qt5\dbinit-regression-*.txt`

可选参数：

- `-BuildFirst`
  先重新编译 `LaserSpcDbInit`
- `-CleanupAfter`
  回归完成后删除脚本创建的测试库和测试账号

### 6.5 迁移规则

迁移目录：

`sql/mysql/migrations`

脚本命名规则：

`V001__create_core_tables.sql`

要求：

- 只新增新版本脚本，不回改旧版本脚本
- 每个脚本必须可重复执行或具备兼容判断
- `V001__create_core_tables.sql` 已包含 `point_records.laser_content`

## 7. Docker MySQL 说明

如果 MySQL 跑在 Docker 中，需要注意：

- 数据库只保存表数据和路径字符串
- 点位详情 JSON 文件不保存在 MySQL 容器里
- JSON 文件必须存在于运行 `LaserSpc.exe` 的宿主机目录

当前项目已在构建阶段自动复制：

`seed_data/point_details`

到程序输出目录，因此演示详情 JSON 可以直接被主程序读取。

## 8. 点位详情 JSON

默认演示文件目录：

`<程序目录>/seed_data/point_details`

运行时生成目录：

`<程序目录>/point_details`

可用环境变量覆盖运行时生成目录：

`LASERSPC_POINT_DETAIL_DIR`

当前 JSON 字段：

- `templateFilePath`
- `laserTemplatePath`
- `laserContent`
- `readCodeContent`
- `success`
- `programName`
- `startTime`
- `endTime`

补充说明：

- `templateFilePath` 是当前优先展示字段
- `laserTemplatePath` 继续保留，用于兼容旧 JSON
- 点位详情弹窗会把这些字段转成中文标签展示
- 点位详情目录可在系统设置中配置；留空时默认使用 `<程序目录>/point_details`
- `point_records` 表现已新增 `laser_content` 字段，用于点位记录列表、导出和查重 API

## 9. 生产环境建议

### 9.1 数据库

- 使用专用业务账号，不建议长期使用 `root`
- 设置合理的连接超时与读超时
- 迁移前先备份数据库
- 定期执行“按时间清理生产数据”

### 9.2 配置管理

- 开发、测试、生产使用不同 `ini` 文件
- 生产密码优先通过环境变量注入
- 不要把生产密码提交到代码仓库

### 9.3 种子数据

- 生产环境首次部署建议设置 `LASERSPC_DB_SEED=0`
- 若已误灌种子数据，可在配置中心执行“清理种子数据”

## 10. 常见问题

### 10.1 点位详情弹窗打不开

优先检查：

- `point_records.detail_json_path` 是否为空
- 程序输出目录下是否存在 `seed_data/point_details`
- `detail_json_path` 指向的文件是否真实存在

### 10.2 数据总览有数据，但点位记录和不良统计无数据

通常是：

- `board_records` 有数据
- `point_records` 无数据或时间范围不匹配

建议：

- 先检查库表行数
- 再检查默认查询时间范围

### 10.3 配置中心修改后不生效

检查：

- 是否成功保存到 `config/laserspc.ini`
- 是否有环境变量覆盖了同名配置
