# 当前进度与下一步

## 一、当前阶段判断

项目已经从“Qt AOI 展示壳子”进入到：

**虚拟设备可闭环联动的工业 AOI / 镭雕一体化上位机原型。**

当前已经具备三条真正可演示的主链路：

1. **虚拟运动控制链**：相机轴、激光轴、运输挡板、进板/出板统一由 `VirtualMotionSystem` 驱动  
2. **虚拟相机链**：基于整板 demo 图，按机械坐标实时裁切 FOV，替代真实工业相机  
3. **业务流程链**：整板扫描、Mark/原点/激光步骤、运行日志、运行预览已经能跟随虚拟设备动作同步变化  

当前最重要的任务已经不再是“补骨架”，而是：

1. **把校正交互做完整**（P0）  
2. **把虚拟相机/虚拟物理卡坐标体系接到所有编辑和校正入口**（P0）  
3. **继续减少 MainWindow 中的交互拼装代码，把设备语义收拢到更清晰的模块边界**（P1）  

## 二、当前已具备的基础

### 1. 虚拟运动与运输系统 ✅

- `VirtualMotionController` 负责轴级运动
- `VirtualTransportController` 负责进板 / 出板 / 挡板状态机
- `VirtualMotionSystem` 负责对业务暴露统一 API：
  - 相机轴移动 / 回零 / 等待完成
  - 进板 / 出板 / 挡板 / 运输等待
  - 统一 tick，保证动画、流程、UI 状态共用一套节拍

### 2. 虚拟整板相机 ✅

- 新增 `camera/VirtualCameraDevice`
- 基于 `demoimage/board.png` 实时裁切 FOV
- 当前画面会随以下因素同步变化：
  - `CameraX / CameraY / Z / R`
  - 当前板尺寸、FOV 尺寸
  - 板是否到位、运输当前位置
  - 挡板右下参考位与逻辑整板原点之间的映射
- 主界面预览、运行界面预览、整板扫描、原点/Mark/激光偏移对话框已经走这条链路

### 3. 原点语义转换 ✅

已经明确并落地两套坐标语义：

- **用户感知物理语义**：
  - 挡板在工位右下侧
  - 板从左往右进，到右侧挡板定位
  - 用户在挡板参考角点做原点相关操作

- **内部业务逻辑语义**：
  - 整板扫描、程序编辑、Mark/ROI、拼图规划仍以整板逻辑左上为原点
  - 原点校正窗口拿到右下挡板参考位后，会自动换算并保存为逻辑整板原点

这一步很关键，因为它保证了“工位观感真实”与“流程算法不镜像”可以同时成立。

### 4. 设备动画与运行界面 ✅

- 运控动画已经修正为：
  - 板从左往右进
  - 右侧下方挡板定位
  - 相机/激光头默认停在右侧参考区域
- 运行界面右侧已使用滚动区
- 左侧运行预览已叠加：
  - 当前步骤
  - 当前轴位
  - 板状态
  - OK/NG
  - 物理卡坐标
  - 板尺寸 / 轨宽

### 5. 流程与扫描链路 ✅

- `WorkflowContext::moveCameraPose` 已接到统一虚拟运控 API
- 整板扫描已优先使用统一虚拟运控移动回调
- 扫描结果、Mark 流程、激光执行、运行界面日志都能跟随模拟设备动作前进

### 6. 回归测试 ✅

当前核心测试已扩展到 `59` 项，全部通过，新增覆盖：

- `VirtualMotionSystem`
- 运输一轮完成后再次装板 / 继续移动相机轴
- `VirtualCameraDevice` 随机械坐标切换不同 FOV

## 三、当前最重要的剩余问题

### P0 — 校正交互还不完整

虽然虚拟相机和坐标语义已经打通，但校正交互仍然不够“设备化”：

#### 1. 原点校正窗口仍然偏“冻结图像 + 应用结果”

当前缺少：

- 左右布局
- 左侧实时取景
- 右侧上下左右点动按钮
- 相对步长设置
- 当前机械坐标显示
- 当前图像像素坐标显示
- “设置当前点为原点参考位”这类明确动作按钮

#### 2. 镭射点偏移校正窗口需要升级为完整业务窗口

当前虽然已有 `LaserOffsetCalibDialog`，但它还不是和原点校正窗口同等级的“设备交互式校正窗口”。

下一步应该把它做成：

- 与原点校正窗口相同的左右结构
- 左侧实时虚拟相机画面
- 右侧运动控制按钮和步长
- 显示机械坐标 / 图像像素坐标
- 显示当前相机点 / 镭射点的偏移量
- 支持“记录当前点”“应用偏移校正”

#### 3. Mark 偏移校正窗口应退出主线

当前产品语义里更重要的是：

- 原点校正
- 镭射与相机偏移校正

因此 `MarkOffsetDialog` 不应该继续作为主线校正入口存在，需要逐步移除。

### P0 — 编辑界面“定位到选中”还没完全虚拟设备化

编辑界面右侧的“定位到选中的”功能现在还需要继续收口：

- 选中 Mark / ROI / 镭射点后
- 应通过统一虚拟物理相机系统移动到目标点
- 左侧 FOV 预览立即变化
- 运控动画与运行预览可观察到对应坐标变化

### P1 — 设备交互代码还需要进一步模块化

当前 `MainWindow` 已经不像以前那样承担全部业务，但设备交互仍有不少 glue code。

下一步适合逐渐收拢出：

- `VirtualCameraDevice` 周边的坐标映射辅助类
- 校正窗口通用控制面板
- 统一的“相机点动 / 步长 / 当前坐标 / 当前像素”组件

## 四、下一步开发优先级

### P0（下一轮最优先）

1. **重做原点校正窗口**
   - 左右布局
   - 左侧实时 FOV
   - 右侧点动控制 + 步长
   - 当前机械坐标 / 图像像素坐标
   - 设置原点按钮

2. **重做镭射点偏移校正窗口**
   - 复用原点校正窗口的交互骨架

3. **移除 Mark 偏移校正窗口**
   - 从菜单、工具栏、主流程入口中移除

4. **编辑界面“定位到选中”接入虚拟相机系统**
   - 选中对象
   - 计算目标机械坐标
   - 调用统一虚拟运控 API

## 五、推荐演示路径

### 演示 1：虚拟相机 + 运控联动

```text
打开程序
→ 打开运控面板
→ 进板
→ 板到右侧挡板定位
→ 点动相机 X/Y
→ 主预览实时切换到整板不同区域
→ 运行界面同步显示当前卡坐标与板坐标
```

### 演示 2：虚拟原点语义

```text
打开原点校正窗口
→ 把相机移动到挡板右下参考位
→ 设置当前参考位
→ 系统内部换算并保存逻辑整板原点
→ 执行整板扫描
→ 扫描结果仍按逻辑左上坐标正常规划
```

### 演示 3：整板扫描

```text
载入程序
→ 进板
→ 启动整板扫描
→ 相机轴按 FOV 网格移动
→ 每个 FOV 画面跟着变化
→ 生成整板拼图
```

## 六、当前最不该做的事

1. 不要把新的校正交互继续临时写进 `MainWindow`
2. 不要重新把真实 Mac 摄像头路径混回主预览链
3. 不要在没有统一步长 / 点动 / 坐标显示组件的情况下分别复制窗口逻辑
4. 不要让原点校正和镭射偏移校正继续使用不同的交互范式
5. 不要把右下挡板物理语义直接扩散到整板扫描算法内部，转换层必须保留
